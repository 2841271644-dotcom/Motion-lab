MOTION LAB V2.7 检查报告

一、针对卡在 42% 的根因
- V2.6 在主线程直接 await import(jsDelivr ESM)，没有给该动态导入设置超时；CDN 请求挂起时，任务会一直停在“正在连接转换资源”。
- FFmpeg Worker 入口也通过动态 import 远程 worker 模块，旧版本没有对该导入设置超时。
- V2.7 为模块导入、核心文件下载、本地 Worker 检查和 FFmpeg.load 设置超时，并在失败后切换备用线路。
- 新增 GitHub Actions 构建：部署时通过 npm 安装依赖，并把 FFmpeg ESM、FFmpeg Core WASM、SVGA Player、Lottie、JSZip、JSZipUtils 复制到 Pages 同源目录。

二、用户提供的 SVGA 样本
- 文件：000(2).svga
- 版本：SVGA 2.1.0（zlib + Protobuf）
- 画布：300 x 300
- 帧率：15 FPS
- 时长：2 秒
- 帧数：30
- 30 个嵌入 PNG 均可完整解码。
- 从样本提取的 30 张 PNG 帧均为 300 x 300，图像完整性检查通过。

三、本机 FFmpeg 编码验证（基于该 SVGA 样本的 30 帧）
- SVGA 帧序列 -> MP4：通过，H.264，300 x 300，15 FPS，30 帧。
- SVGA 帧序列 -> WEBM：通过，VP9，300 x 300，15 FPS。
- SVGA 帧序列 -> 动态 WEBP：通过，Pillow 验证 300 x 300、30 帧。
- SVGA 帧序列 -> GIF：通过，Pillow 验证 300 x 300、30 帧。
- SVGA 帧序列 -> APNG：通过，Pillow 验证 300 x 300、30 帧。
- MP4 -> 动态 WEBP：通过，Pillow 验证 300 x 300、30 帧。
- 动态 WEBP -> MP4：通过，H.264，300 x 300，15 FPS，30 帧。
- MP4 帧序列 -> SVGA 1.x ZIP/JSON：ZIP 根目录包含 movie.spec 和 30 张 PNG，结构检查通过。

说明：FFprobe 对部分动画 WEBP 文件的流信息识别不完整，因此动态 WEBP 使用 Pillow 检查帧数和尺寸，不以 FFprobe 单独作为通过标准。
